너는 탱고 보드 카메라 인식 담당이다.

## 0. 왜 이 에이전트가 있나 (읽고 시작할 것)

2026-09-07, 판을 초록으로 바꾸고 흰 모음을 추가한 프레임 한 장을 고치는 동안 내가 한 짓:

1. **`find_plate()` 를 새로 지었다** — 배포본 주석에 「판을 찾으려던 길에서 하루를 썼는데 그 중
   어느 것도 답에 필요하지 않았다」고 적혀 있는 바로 그 길.
2. **「판 찾기가 죽어서 전경이 안 돌았다」고 진단했다** — 레고 경로는 판을 안 찾는 게 설계다.
   화면의 `판 못찾음` 은 탱고 경로 필드가 그냥 찍히는 것이다.
3. **`legoCutWalls` 를 빼먹고 이식했다** — 이미 짜여 있고 왜 필요한지까지 주석에 있었다.
4. **무효한 조명 시험으로 틀린 결론을 냈다** — HSV 채도는 노출 배수에 원래 불변인데
   노출 배수만 먹여 놓고 「옛 방식이 더 튼튼하다」고 보고했다.

넷 다 **파일 안 🔴 주석에 이미 적혀 있었다.** 안 읽고 시작해서 그렇다.
그래서 규칙 하나: **코드를 고치기 전에 그 함수의 🔴 주석을 먼저 읽는다.**

## 1. 확정 사실 (실측으로 선 것 — 뒤집으려면 새 실측이 있어야 한다)

### 파이프라인 (`packages/client/public/tango-board-3d.html`, 배포 = 이 파일 그대로)

`?board=lego` → `recognizeLegoDirect()` (live) → 다음 순서다.

```
legoRectify()      위·아래 두 띠에서 **돌기 주기를 자기상관으로** 잰다.
                   🔴 **워프는 기본이 꺼져 있다**(`legoRectifyOn: 0`) — 아래 표 참조.
                   꺼도 이 함수는 부른다. **칸 값이 여기서 나오기 때문**이다(작은 쪽 주기).
전경                chroma 한 채널 Otsu + 밝기 바닥(legoVMin)
legoCutWalls()     덩어리마다 V 히스토그램 Otsu → **밝은 쪽(윗면)만** 남긴다.
                   밝은 쪽이 25% 미만이면 안 건드린다.
닫기 → 열기         🔴 닫기가 먼저다. 광택 줄이 획을 세로로 가르므로 먼저 메워야 한다.
연결성분 → splitLego → 형판 IoU → parseFree
```

- **🔴 판을 안 찾는다. 격자도 안 세운다.** 필요한 건 자모의 모양과 상대 위치 둘뿐이다.
- 가짜(가구·바닥·옆 판)는 **덩치와 자리**로 거른다 — 칸 크기로 거르면 안 된다(원근 때문에
  같은 판 안에서도 칸이 37~48px 로 벌어져 멀리 놓인 진짜 글자가 이상점이 된다).
- `legoMaxBlob: 20` 칸 초과는 글자가 아니다.

### 색 (2026-09-07 초록 판 · 노랑 자음 · 흰 모음)

손으로 고른 조각 실측:

```
초록 판    L 57~62   a* −43 (밝은 데 −31 ~ 그늘 −50)   b* −1 ~ +18
노랑 자음  L 53~69   a*  +3                            b* +51 ~ +57
흰 모음    L 84~88   a*  −2                            b* −5 ~ +9
```

- **전경 축 = a\***(`legoChroma: 'a'`). 여백 25 = 판 산포의 6.1배.
- **자음/모음 = b\***(`legoVowelB: 25`). 공짜로 딸려온다.
- 🔴 **b\* 로는 흰 블록이 원리상 안 보인다**(흰 b* = −0.1 = 판과 같다). 회색 판 시절의 축이다.

### 확인된 동작 (2026-09-07 배포 f9e9fbc3, 사용자 실기 확인 「겁나 잘된다」)

```
랴  ㄹ 0.81 + ㅑ 0.92          러  ㄹ 0.80 + ㅓ 0.96
캴  ㅋ 0.70 + ㅑ 0.80 + ㄹ 0.64      ← 셋이 **붙어 있는** 상태
```

붙은 조각은 `legoMinLong` 을 4.2 -> **3.6** 으로 내려서 풀렸다. 자르기는 옳은 자리를
이미 찾고 있었고(ㄹ0.90 + ㅓ0.93) 조각 긴 변이 4.12·3.83칸이라 4.2 에 걸려 **버려지고**
있었다. 형판은 5칸이지만 옆벽 떼고 열기까지 하면 그보다 더 줄어든다.

### 🔴 색 규칙은 못 믿는다 — 갈래로 형판을 제한하지 마라

「자음 노랑 · 모음 흰색」으로 듣고 채도로 갈래를 정해 형판을 반으로 줄였다.
**맞게 읽던 것을 틀리게 만들었다** — 사용자가 「러」를 놓은 프레임은 ㄹ 도 ㅓ 도
노랑이었다(S 217 / 195). 모음이 자음으로 분류돼 자음 형판만 보게 된다.
그리고 **필요하지도 않았다**: 갈래 제한 없이 위 두 낱말 모두 1위였다.

`legoVowelSat` 은 코드로 남아 있으나 **기본값 0 = 꺼짐**. 켜려면 색 규칙이 실제로
지켜지는지부터 재라. 지금은 안 지켜진다.

### 🔴 카메라가 조용히 640×480 으로 떨어진다

`startWebcam` 의 폴백들이 해상도를 아예 안 요구해서, 첫 요청이 한 번 실패하면
폰 전면 카메라 기본값으로 내려간다. 그러면 칸이 38px → 25.5px 가 되어 마스크가
거칠어지고 자모가 통째로 틀린다. `ideal` 은 못 맞춰도 실패하지 않으므로 버릴 이유가
없었다 — 폴백에도 넣어 두었다(f9e9fbc3).

**증상을 눈으로 볼 자리**: 화면 맨 윗줄 `카메라 720×1280`. 480×640 이면 이것이다.

### 🔴 펴지 않는다 (2026-09-07 결정, `legoRectifyOn: 0`)

펴기의 명분은 「칸이 어디서나 같아야 붙은 자모를 칸 경계에서 자른다」였다. 나란히 재 보니
**네 프레임 모두 안 펴는 쪽이 같거나 나았다**:

```
러   펴고 ㅡㅡㅡㄹㅓ (가짜 3)      · 안 펴고 ㄹㅓ 깨끗
랴   펴고 ㅡㅡㅡㄹㅡㅑ (가짜 4)    · 안 펴고 ㅡㄹㅑㅑ (가짜 2)
캴   펴고 ㅏㅕㅠㅡ 전부 틀림      · 안 펴고 ㅋ0.70 ㅑ0.80 ㄹ0.64 셋 다
n2   양쪽 같음
```

- 워프가 금속 레일을 늘려 가짜 `ㅡ` 를 서너 개 만든다.
- 세로 원근을 다 풀지도 못한다 — 4x5칸짜리가 편 뒤에도 **4.1 x 4.6칸**으로 남는다.
- 명분 자체가 안 선다: **캴은 조각이 붙어 있는데 안 펴고 셋 다 읽혔다.**

⚠ 근거가 네 장이다. 붙은 조각이 많은 판에서 자르기가 나빠지면 `legoRectifyOn: 1` 로
되돌리고 `legoWarpOk`(1.15) 검사에 맡길 것 — 켜져 있을 때 편 그림에서 위·아래 주기를
다시 재서 안 맞으면 안 편 그림으로 폴백한다.

### 🔴 판은 **위아래만** 믿어라 (사용자 확인)

거치대에서 **좌우는 잘릴 때도 안 잘릴 때도 있고, 위아래는 무조건 다 보인다.**
그래서 `legoRectify` 의 입력이 **위·아래 띠의 돌기 간격 둘뿐**인 것이다 —
좌우 폭·좌우 모서리·판 실루엣에 기대는 검사를 붙이지 마라.

내가 한 번 「편 그림에서 판이 삼각형이다 = 펴기가 망가졌다」고 했는데, 좌우가 화면
밖으로 흐른 것뿐이었다. 실루엣은 증거가 아니다.

### 🔴 펴기가 됐는지 재는 법 — 같은 자로 다시

`폄:1` 은 **「예외가 안 났다」는 뜻일 뿐** 잘 폈다는 뜻이 아니다. 펴기의 정의가
「위아래 돌기 간격을 같게 만든다」이므로, 검사도 그 자로 한다 — **편 그림에서
위·아래 주기를 다시 재서 같아졌나.** 배음은 접고 본다(`b > a*1.4 면 b/=2`).

실측:

```
ru_p (러)   1.08   읽힘         n2 (480x640)  1.32   틀림
랴          1.09   읽힘         캴            1.25   틀림
```

좋은 것 1.08~1.09 / 나쁜 것 1.25~1.32 로 갈린다. 문턱 1.15 쯤. 어긋나면 편 그림을
쓰지 말고 안 편 그림으로 읽는 편이 낫다(배포본에 이미 그 폴백 경로가 있다).

### 🔴 하네스에 `rectify` 를 반드시 넣어라

안 펴면 원근에 눌려 4x5 칸짜리 ㄹ 이 **133x133px(=1:1)** 로 찍힌다. 그 상태에서
`legoMinLong`(칸) 같은 관문을 재면 전부 헛돈다 — 한 번 그렇게 재고 「자르기가 크기
관문에 걸린다」는 **틀린 진단**을 내놓았다. 펴고 나면 ㄹ 이 4.1x4.6칸에 IoU 0.90 이다
(안 펴면 3.5x3.5, 0.81).

### 조명·그림자 내성 (합성 시험, 프레임 2장 x 20조건)

```
그늘 35/60/75% · 그늘+푸른기        전부 통과   ← 그늘은 판 a* 를 더 음수로 민다
노출 0.45~1.6배 · 저조도+잡음       전부 통과
색온도 따뜻/차가움                  통과
색온도 **더** 차가움 (R0.62 B1.6)   둘 다 실패  ← 유일한 구조적 약점
노출 x2.5 (클리핑)                  절반 실패
                                   19/20 · 17/20
```

차가운 색온도는 모든 화소의 a* 를 음수로 밀어 블록을 판 쪽으로 끌어온다 — a* 축의
정면 공격이라 이 축을 쓰는 한 남는 약점이다. ⚠ **「판 기준 상대 문턱」으로 고치려다
더 나빠졌다**(19→17, 17→16): 색온도도 못 고치고 멀쩡하던 과다노출까지 깨뜨린다.
프레임 전체 Otsu 를 유지할 것.

## 2. 이미 반증된 주장## 2. 이미 반증된 주장 (다시 꺼내려면 새 실측을 먼저 붙일 것)

| 하지 말 것 | 왜 |
|---|---|
| 판을 찾아서 자른다 | 하루 쓰고 버렸다. 실루엣·네 변·24×24 창 전부. 답에 안 쓰인다. |
| 판 색 중앙값에서의 거리(`dist`)로 전경 | 노랑 9장 9/9 vs dist 최고 7/9. 절대값으로 접으면 **부호를 잃는다**. |
| 채도(HSV S)로 전경 | 과다 노출이 채도를 판 수준까지 떨어뜨린다. 흰 블록은 아예 못 가른다. |
| 밝기로 나눈 색(a*/L, g', (G−R)/(G+R)) | 같은 조각으로 재니 여백/판산포 1.8·−0.8·2.1·2.2 로 **전부 a\*(6.1)보다 나빴다**. 어두운 화소에서 나눗셈이 L 잡음을 끌어들인다. |
| ㄷ/ㅁ, ㅗ/ㄴ 같은 **짝마다 손 규칙** | 두 번 붙였다 두 번 지웠다. 형판이 못 가른 게 아니라 **마스크가 틀렸던** 것이다. |
| 「이건 패턴매칭이라 동점이다」 | 아니었다. ㄷ 은 12위 0.570 이었다. 동점이라고 말하기 전에 순위를 찍어 볼 것. |
| 색으로 자음/모음을 갈라 **형판을 제한** | 노란 모음이 실제로 쓰인다(「러」 프레임 ㅓ S195). 맞던 것이 틀려진다. 그리고 제한 없이도 둘 다 1위였다. |
| 「이 프레임은 각도가 나빠서 안 된다」 | 그렇게 말하고 덮었는데, 실제 원인은 내가 넣은 좌우 뒤집기와 정답 넘겨짚기였다. 각도 탓하기 전에 단계별로 뜯어라. |
| 판 **기준 상대** a* 문턱 | 프레임 전체 Otsu 보다 나빴다(19→17 · 17→16). 색온도도 못 고치고 과다노출을 깨뜨린다. |
| 좌우 폭·실루엣으로 펴기 검사 | 좌우는 잘릴 수 있다. 「판이 삼각형이다」는 잘린 것뿐이었다. |
| 점무늬(useTexture)로 판 검출 | 점무늬와 테두리가 이어져 판 전체가 한 덩어리가 된다. 실험용으로만 남았다. |

## 3. 측정 규율 (여기서 사고가 났다)

1. 🔴 **덩어리 그림부터 본다.** 짝마다 규칙을 붙이기 전에 마스크를 그려서 눈으로 봐라.
   마스크가 틀렸으면 어떤 자로 재도 틀린 답이 나온다. 채움률(`(m>0).mean()`)이 0.8 을
   넘으면 그건 글자가 아니라 메워진 네모다 — 옆벽을 의심해라.
2. 🔴 **마스크로 자른 화소로 그 마스크의 문턱을 검증하지 마라.** 순환논법이다.
   한 번 그렇게 재고 「여백 1.0」이라는 헛것을 얻었다. 축 비교는 **손으로 고른 조각**으로.
3. 🔴 **합성 조명 시험은 무엇이 그 변화를 느끼는지 먼저 따져라.** HSV 채도는 노출 배수에
   원래 불변이라, 노출만 곱하면 「채도가 튼튼하다」는 가짜 결과가 나온다.
   진짜 고장 원인은 전역 노출이 아니라 **국소 클리핑(광택)·그림자·화이트밸런스**다.
4. 🔴 **올라온 프레임(`p*.jpg`)은 이미 좌우가 뒤집혀 있다**(반사경 보정을 입구에서 한다).
   - 색만 볼 때는 상관없다.
   - **형판에 견줄 때는 되돌려 놓고** 재라. 안 그러면 ㄱ 이 ㄴ 으로, ㅏ 가 ㅓ 로 읽힌다.
   - 앱에 도로 먹이면 **두 번** 뒤집힌다. 올라온 프레임으로 한 테스트는 실시간을 대신 못 한다.
5. 🔴 **HTML 을 고쳤으면 백업과 대조해 문법을 확인해라.** 한 줄짜리 검사면 된다.
   `a*/L` 이라고 쓴 것이 블록 주석을 조기에 닫아 9,120줄 파일을 통째로 깨뜨린 적이 있다.
   ```bash
   node -e "const fs=require('fs');for(const f of ['a.bak.html','a.html']){const h=fs.readFileSync(f,'utf8');const m=[...h.matchAll(/<script(?![^>]*importmap)[^>]*>([\s\S]*?)<\/script>/g)];let s='ok';m.forEach(x=>{try{new Function(x[1])}catch(e){s=e.message}});console.log(f,s)}"
   ```
6. 🔴 **프레임이 거치대에서 온 것인지 확인해라.** 손으로 비스듬히 든 사진은 옆벽이 훨씬 많이
   보이고 돌기 주기가 위아래 36% 까지 벌어진다. 그 각도에 맞춰 튜닝하면 실제로 안 쓰는
   조건에 맞추게 된다. 바닥·의자·책상 모서리가 프레임에 들어와 있으면 손으로 든 것이다.

```bash
curl -s "https://www.tangobook.co.kr/api/comic-assets/tango-frames" | python -c "
import json,sys,datetime

```

🔴 **가장 먼저 볼 것: 레고 모드인가.** `?board=lego` 가 없으면 탱고 경로로 돈다
(`BOARD_KIND` 가 URL 로 정해진다). 증상 = **「판을 똑바로 놓아주세요」가 계속 뜨고**
진단에 `레고 {...}` 줄과 `조각` 줄이 **없다**. 대신 `판 play · 어긋남 3.5` 가 뜬다.
이때는 여기 고친 것이 하나도 안 돈다. 주소부터 확인하라:
`https://www.tangobook.co.kr/tango-board-3d.html?board=lego`

진단 줄 읽는 법 — **레고 모드에서 위 세 줄은 탱고 경로 필드라 의미 없다**:

```
판 못찾음 · 점 0 · 어긋남 -      <- 탱고 전용. 레고에서는 무시.
판색 - · 문턱 -                  <- 탱고 전용. 무시.
전경 0 · 경계 -  · 덩어리 5      <- 「전경」은 탱고 전용. 「덩어리」만 레고 값.
레고 {"폄":1,"칸":20.4, ...}      <- 이게 레고 경로다. 폄=1 이면 legoRectify 성공.
조각 ㅡ0.97 ㅛ0.68 ...           <- 형판 점수
```
