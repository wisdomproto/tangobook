## 1. 새로 생긴 재고 — 한글 파닉스 36편

우리 웹 블로그(ko)에 **전부 발행 완료·프로덕션 라이브**. sitemap 반영 + IndexNow 제출까지 끝났다.

| 묶음 | 편수 | 슬러그 예 |
| --- | --- | --- |
| 단원 글 | 32 | `hangul-consonant-giyeok-teaching` · `hangul-batchim-siot-teaching` · `hangul-double-consonant-ssanggiyeok-teaching` · `hangul-vowel-ae-e-teaching` |
| 허브 글 | 4 | `hangul-jamo-order-guide` · `hangul-batchim-guide` · `hangul-double-consonant-guide` · `hangul-teaching-order-guide` |

- 단원 = 모음 1 · 자음 14(ㄱ~ㅎ) · 받침 7 · 쌍자음 5 · 복잡한 모음 5. 커리큘럼 32단원과 1:1.
- 각 편 6섹션 + **학습 화면 스크린샷 3장**(앱을 직접 크롤해 찍은 것).
- 허브→단원 **내부링크 78개, 죽은 링크 0**. 32단원 전부 허브에서 도달 가능.
- DB: `mkt_contents.memo='storybook:kr-h1-u02'` 꼴(허브는 `storybook:hub-batchim`), `category='phonics'`.
- 정본은 **블로그 JSON**(`scripts/_data/marketing/blogs/`), 기본글은 파생물
  (`build-phonics-base-articles.mjs`). 🔴 기본글을 손으로 고치면 다음 빌드에 날아간다.

⚠️ **웹에는 「직접 해보는 학습 활동」이 본문 중간에 임베드**돼 있다(진짜 파닉스 활동 컴포넌트).
네이버엔 못 간다 — 그 자리를 무엇으로 메울지 판단 필요.

## 3. 실측 — 네이버 채점 (`score-naver-seo.mjs --category=phonics`)

```
36편 · 평균 66점 — A 0 · B 0 · C 36 · D 0
```

| 항목 | 상태 | 배점 |
| --- | --- | --- |
| 🔴 FAQ | **36편 전부 없음** | 0/9 |
| 🔴 이미지 | 3장 (5장부터 만점) | 14/24 |
| 🟡 본문 길이 | 1,022~2,110자 (1,500부터 만점) | 21/35 |
| 🟢 소제목 | 6개 | 18/18 |
| 🟢 제목 키워드 | 34편 포함 / **허브 2편 없음** | 14 또는 0 |

비교: 생활동화 93 · 자연관찰 90(A 28편) · 세계명작 83.

🔴 **허브 2편이 0점인 이유 = 띄어쓰기**(실측 확인).
`titleHasKeyword` 가 **문자열 포함**으로만 재는데, 네이버 키워드 도구는 공백을 붙여 준다.
- `한글떼기` vs 제목 `4~7세 한글 떼기 — …`
- `자음모음` vs 제목 `한글 자음 모음 순서 — …`

→ 제목을 붙여 쓸지(검색어와 일치하지만 어색함), 채점기를 공백 무시로 고칠지, 아니면
`primary_keyword` 를 띄어쓴 형태로 바꿀지 — **판단 필요**. 어느 쪽이 실제 유입에 유리한지는 안 쟀다.

## 5. 판단해 줄 것

1. **파닉스를 로테이션에 넣나?** 넣는다면 기존 순서
   (자연관찰 → 전래 → 명작 → 세상탐험 → 생활·유치원) 어디에.
2. 넣는다면 **8/12 배치 14편 구성**은? (현재 계획 = 자연 70 / 전래 20 / 명작 10)
3. **허브 4편 먼저 vs 단원 32편 먼저.** 허브는 큰 키워드지만 전부 HIGH, 단원은 롱테일.
4. **채점 66점을 올릴지, 올린다면 무엇부터.** FAQ(9점) · 이미지(10점) · 길이(14점) 중.
   생활동화에 FAQ를 붙인 `add-blog-faq.ts` 가 파닉스에도 쓰일 수 있는지.
   🔴 단, 에이전트 §2 ② = **글 길이로 발행 순서를 정하지 마라**. 점수는 품질 신호지 순서 근거가 아니다.
5. **허브 제목 띄어쓰기**(위 §3) 를 어떻게 할지.
6. **웹 임베드가 빠지는 자리**를 네이버에서 무엇으로 메울지.

## 6. 제약

- 🔴 **발행·예약하지 말 것.** 판단과 계획까지. 실행은 사용자 승인 후.
