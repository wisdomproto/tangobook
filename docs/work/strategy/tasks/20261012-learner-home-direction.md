## 요청과 범위

사용자는 플랫폼 정체성 정리를 바탕으로 메인화면 개편을 먼저 고민하자고 요청했다. 선택 질문에 **학습하기에 들어간 뒤의 앱 첫 화면**이라고 명확히 답했다. 공식 사이트 소개 화면 개편이나 코드 구현을 요청한 것이 아니다.

## 확인한 기준과 현재 화면

- 현재 정체성과 상품 방향은 [PLATFORM.md](../../../PLATFORM.md)를 따른다. 소개서 승인과 기준 문서 정리는 [이전 작업](20261012-platform-main-document.md)에 있다.
- `packages/client/src/pages/LibraryPage.tsx`와 `packages/client/src/components/AppShell.tsx`를 읽고 운영 `/library`를 브라우저로 확인했다.
- 현재 첫 화면은 동화책 서재다. 한 권 들어보기, 묶어 보기, 검색·카테고리, 동화책 가로 목록이 먼저 보인다. 주 메뉴는 동화책·독후 게임·파닉스다. 로그인 상태에 따라 부모 메뉴·프로필이 보인다.
- 제품 디자인 기준은 [design-system.md](../../../design-system.md). 플랫폼 설명이나 내부 사업계획서가 아니라 아이가 직접 활동을 시작하는 화면이라는 역할이 중요하다.

## 검토 제안 — 사용자 미승인

- 별도 학습 홈을 두고 기존 동화책 서재는 동화책 메뉴로 유지하는 방향 검토.
- 상단에 지난 활동 이어 하기, 그 아래 한글·영어·동화책·게임의 큰 선택 카드 검토. 첫 방문은 시작할 활동을 보여 주고, 기록 없는 사용자에게 이어 하기를 만들지 않는다.
- 한글·영어 과정에서 블록 조합과 종이 쓰기로 이동하는 선택을 명확히 보이게 한다. 교구 유무와 관계없이 디지털 학습 진입을 유지한다.
- 활동 뒤에는 배운 낱말·읽은 이야기와 관계있는 다음 활동을 제안하되, 모든 사용자에게 같은 학습 순서를 강제하지 않는다.
- 부모 리포트는 부모 영역에서 접근한다. 홈의 안내 강도와 자유 선택의 비중, 메뉴 구성·문구·시각 디자인은 미확정이다.

## 검증과 다음 행동

저장소 코드와 운영 화면의 구조를 읽기 전용으로 확인했다. 새 홈을 구현하거나 사용성·학습 효과를 검증하지 않았다. 사용자와 홈의 역할·주요 선택을 더 논의한 뒤 시안 또는 구현 범위를 정한다. 이번 기록으로 PLATFORM.md의 합의를 변경하지 않는다.

## 2026-10-12 사용자 반증 — 복잡함과 도서 탐색

사용자는 첫 시안이 정신없다고 지적하고 왼쪽 사이드바를 계속 유지해야 하는지 질문했다. 이어 오늘의 추천 도서를 제안하고, 동화책이 약 1,000권 규모가 되므로 찾기 어려울 것이라고 우려했다. 권수는 이번 사용자 설명이며 운영 공개 수를 새로 집계한 결과가 아니다.

- 첫 시안을 승인된 디자인으로 취급하지 않는다. 큰 4개 활동 카드·각 카드 안의 버튼·하단 추천이 한 화면에서 경쟁하는 구성을 재검토한다.
- 기존 사이드바 유지도 확정 사항이 아니다. 상단의 간결한 탐색 탭으로 옮겨 본문 폭을 확보하는 방향을 제안한다. 정확한 메뉴 항목·모바일 배치는 미확정이다.
- 오늘의 추천 도서와 많은 책의 탐색 편의가 후속 설계의 핵심 입력이다. 현재 `LibraryPage`에는 처음 방문 한 권 들어보기와 묶어 보기·검색·분류가 연결돼 있으며 오늘의 추천 도서 섹션은 확인되지 않았다.
- 검토 방향: 작은 이어 하기, 크게 보이는 오늘의 추천 표지 3~4권, 관심 주제별 책 모음, 전체 서재에서 검색/필터. 처음에는 편집 추천을 사용할 수 있고 학습·독서 기록에 따른 추천은 이후 범위로 별도 논의한다. 한글·영어 학습 진입은 유지한다.

이번 응답은 논의와 반증 기록만 갱신한다. 추가 이미지 생성·제품 구현·메뉴 확정은 아직 하지 않았다.

사용자는 이어 "일단 메인 페이지에 집중해보자"라고 범위를 좁혔다. 전체 서재의 상세 검색·필터 설계는 뒤로 두고 메인 화면의 정보 위계와 시각적 단순화에 집중한다. 이전 이미지 시안 요청과 반증을 반영하여 사이드바 없는 두 번째 메인 시안을 준비한다. 실제 구현은 여전히 요청 범위 밖이다.

### 두 번째 시안도 사용자 반증

사용자는 "뭐야이게. 뭔가 짬뽕같은데"라고 두 번째 시안을 거부했다. 이 시안의 단순화·추천 중심 구성을 승인된 방향으로 취급하지 않는다. '오늘의 추천 도서가 필요하다'는 의견을 '메인 전체를 책 추천 중심으로 바꾼다'는 결정으로 확대하지 않는다. 사이드바 제거와 상단 메뉴도 승인된 구현 조건이 아니다.

담당자의 진단은 학습 홈·지난 활동·추천 서재의 역할 위계와 서로 다른 시각 표현을 충분히 정돈하지 못했다는 것이다. 이 진단은 사용자에게 확인받은 세부 거부 이유와 구분한다. 플랫폼 정체성은 기존 PLATFORM.md를 유지하고, 후속은 메인의 주된 역할·학습/동화 추천의 관계·일관된 시각 언어를 먼저 정리한다. 확정 없이 요소를 더 넣거나 바로 또 이미지 생성하지 않는다. 제품 코드 변경 없음.
