## 요청과 완료 조건

- 승인된ㅏ·ㄱ·ㅇ 팝잇을 한글 자음/쌍자음/모음/복잡한 모음 및 영어 대소문자 전체로 확대한다. 실제 학습 연결과 전체 글자 모양·반응형 터치 영역을 검수한다.
- 작업 중 사용자 쓰기 화면 반증: ㄱ 가이드가 미세하게 울며 아래 글씨가 작다. 한글 직선 투영 정리 및 하단 안내/도구의 가독성도 보완한다. 팝잇 확대 요청은 유지한다.

## 방침·진행

- 기존 공통 SVG/HTML 팝잇과 소리/완료 계약 재사용, 쓰기·블렌딩·낱말 판정/기록 키 유지. 정확한 형태를 위해 기존 획 템플릿을 기반으로 조형하고 쌍자음/복합 모음은 간격을 별도 확보한다.
- 영어는 대문자→소문자 팝잇 뒤 해당 글자의 기존 삽화/낱말 탐색으로 연결한다. 탭 전환이나 팝잇 일부만으로 글자 전체 탐색을 완료 처리하지 않는다.

## 구현

- 한글40자·영어 대소문자52자 catalog. 기존 획 템플릿으로 실제 SVG 곡선과 직선을 유지하고, 쌍자음/복잡한 모음의 성분 간격·구멍을 보존한다. 승인된ㅏ·ㄱ·ㅇ 모양/5·5·8방울은 유지한다. 다른 글자는 형태에 맞게 방울을 배치하며 같은 방울 연타는 진도를 늘리지 않는다.
- 글자 경로와 보이는 방울은 가변 크기, 실제 터치 영역은 최소44px이며 서로 겹치지 않는다. 영어는 대소문자 안내를 표시한다. 작은 높이는 왼쪽 안내/진행·오른쪽 글자로 배치하고 긴 진행점은 줄바꿈한다. 기존 공용 뽁 소리/음소거·발음 실패 재시도·칭찬 후 한 번만 완료 계약을 공유한다.
- 한글 가이드 fit에서 영어만 적용하던 직선 정리를 한글에도 적용한다. 실제 마스크 안에 투영한ㄱ도 가로/세로 축을 반듯하게 유지하며 획 순서·판정 허용치는 바꾸지 않는다. 쓰기 하단 안내18~22px, 획 원34px/숫자18px, 다획 줄바꿈을 적용한다.
- DEV 전용 letter-popit-check.html에92자 선택/갤러리/실제 활동/4크기 배치 검사를 추가한다. 학생 진도 저장·숙달 기록·외부 생성/업로드를 하지 않으며 production build entry가 아니다.

## 검증

- 92자 모두8개 갤러리 화면에서 육안 확인. PC1280×720/태블릿1024×768/가로폰844×390/작은568×320 실제 iframe innerWidth/innerHeight ×92자=368배치의 HTML 버튼/진행/안내 좌표 검사: 최소 hit44px, 터치 영역 중첩/화면 밖/글자-문구 충돌0. 이는 브라우저 배치 검사이며 실기기 FPS/손가락 검사와 다르다.
- 실제 브라우저 입력으로ㄲ·ㅃ·ㅙ·ㅞ·i·j·q·W 방울 전부 누르기→첫/최종 발음/칭찬→DEV 완료 신호까지 확인했다. 별도로 실제 영어 en-b1-u01/letters-learn에서 A→a 팝잇→기존 Aa 삽화 탐색 도착, 실제ㄴ 단원 consonant-tap→letter-write 자동 연결을 확인했다. 전체92자 native 완주라고 보고하지 않는다.
