# 한영 낱말 따라쓰기 끝맺음 개선

## 요청·원인

- 사용자는 한영 자유놀이 완주 검수에서 남은 ‘끝부분을 지나치게 덧칠해야 함·통과 후 작은 빈틈’ 개선을 요청했다.
- 낱자 획순 쓰기와 별개인 `WordFillCanvas`가 면적99%를 요구하고, 통과해도 잉크를 정리하지 않아 발생했다. OCR/받아쓰기는 계속 제외한다.

## 구현

- Korean/EnglishWordWritingPlayer가 명시적으로90% 면적 기준을 전달한다. 두 player를 쓰는 배우기/커리큘럼/자유/책 낱말 쓰기에 함께 적용된다. 다른 언어 호출부 기본99%는 유지한다.
- 처음 그린 폰트 마스크를 칸·8방향 연결 영역별로 보관한다.90% 이상이어도 i/j 점이나 한글의 떨어진 획을 통째로 생략하면 거절한다(4픽셀 이상 연결 영역은 절반 이상 직접 칠해야 함). 연결된 획 각각의 필순을 검사하는 기능은 아니다.
- 완료한 칸만 원래 폰트의 emerald 색·원래 alpha로 채워 작은 구멍/회색 끝을 없앤다. 투명한 배경·다음 칸/이전 칸 잉크는 그대로 둔다. 미완성 입력도 손을 떼거나 취소해도 지우지 않는다.
- 한 번 누르고 있는 드래그는 시작한 한 칸에만 귀속한다. 이동 중 완료돼도 다음 칸을 이어 칠하지 않으며, 새 입력으로 다음 칸을 시작한다. 순차 칸만 평가하고 영어 라임 우선 순서·단일 완료/음성 콜백을 유지한다.
- 프레임당 한 번 채점 유지. 마스크 연결 영역은 최초 폰트 준비 때만 계산한다. 기존 연습/독립 성취 기록은 변경하지 않는다.

## 검증

- client typecheck·변경6소스 eslint 통과. client production build40.16초 통과(기존 chunk 크기/i18n 혼합 import/lottie eval 경고).

## 로컬 통합

11회귀·타입·lint·build를 마친 코드와 기억을 함께 로컬 커밋하는 범위다. 실제 root main에 fast-forward로 통합하며, 원격 push/운영 배포는 하지 않는다.

## 메인 푸시 요청

- 사용자가 후속으로 “좋아. 메인에 푸시하자”라고 승인했다. 위 미푸시는 당시 상태다.
- 실제 root main=3eb0800dc, fetch 후 origin/main=76ae2c60a, left/right=0/3. 미푸시3개는 운영 검수 기록5280533b0·자유 블록 결과 재시작 맞춤8c1c1c415·낱말 쓰기 끝맺음3eb0800dc로 같은 후속 작업 범위다.
- 추적 변경 없음·전달 diff/check 확인. 기존 미추적 output/tmp는 보존한다. 앞선11회귀·타입/lint/build·실제 입력 검증 이후 제품 코드 변경은 없다.
- 사용자 승인 기록과 함께 main에 일반 push하고 원격 SHA 일치를 확인한다. 배포 완료·운영 재검수는 이 push 성공과 별개다.
