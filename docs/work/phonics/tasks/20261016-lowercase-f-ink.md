사용자가 운영 D/E/F 쓰기의 소문자 f를 아래로 그을 때 잘 안 채워진다고 보고했고, 첫 획 완료 체크/두 번째 획 안내인데 윗부분만 초록색인 스크린샷으로 반증했다. 앞선52자 판정 검사는 경로 합격만 확인해 획별 잉크 소유권 오류를 잡지 못했다. 곡선 첫 획과 가로획의 소유권/안내 경로를 함께 확인한다. 운영 전체 곡선 native 입력으로 검증했다고 확대하지 않는다.

## 원인과 수정

- `strokeOwners`의 직선 획 폭 추정이 중간35/50/65%에서만 이루어졌다. f의 짧은 가로획은 세 위치 모두 세로 기둥 안이어서, 세로 기둥 전체 높이를 가로획 두께로 잘못 등록했다. 따라서 첫 획 추적은 정상 완료돼도 잉크는 윗곡선만 채워졌다. 판정 임계값 결함으로 단정하지 않는다.
- 폭 표본을10~90% 아홉 곳으로 넓히고, 해당 획 길이보다 긴 수직 방향 잉크 구간은 다른 교차 획으로 보고 제외한다. 유효 표본이 없으면 기존 최근접 경로 소유권으로 폴백한다.
- f의 윗곡선 뒤 세로 구간과 t의 아랫곡선 앞 세로 구간도 긴 직선 구간으로 찾아 먼저 쓴 기둥이 교차점까지 연속해서 채워지게 했다. 한글도 사용하는 공용 분할 함수이며, 가이드/90% 판정/음성/진도는 변경하지 않았다. 설정 시 계산만 추가하며 pointer move의 픽셀 계산은 추가하지 않는다.
- DEV 알파벳 검수판의 기존 전체 검사에 실제 글꼴/획별 누적 채움107장 미리보기를 추가했다. 판정 통과와 별도로 육안으로 채움을 확인하고 JSON에 같은 이미지를 보존한다. 운영 사용자 페이지/학습 진도에 노출하지 않는다.
