# 코타 참조·의상 프롬프트 검토

2026-09-22. 사용자: 대부분의 등록 삽화는 이미 수정해서 넣었으므로 멀쩡하며, 프롬프트 자체를 확인하라고 정정했다. **등록 이미지를 과거 생성 오류의 증거로 쓰지 않는다.** 이미지 육안 비교·생성·수정 없이 텍스트와 복사 경로만 조사했다.

## 확인한 결함

1. `kota-cast.md`의 코타 규격에는 `CLOTH: a short lined robe in OCHRE`, 아빠에는 `deep AZURE #3B5A72`가 있다. 개별 캐릭터 시트 프롬프트는 전문을 받는다. 하지만 `kota-core.js` 및 `_series-core.template.js`의 `castLegend`는 규격의 첫 줄을 110자까지 잘라 페이지 프롬프트에 넣는다. 실제 첫 줄은 BUILD 체형 설명이므로 의상 절이 빠진다.
2. Node VM에서 현행 `composeBatchPrompt`를 01·07권 실제 SCENE/SH_GUESTS로 실행했다. `@image1` 코타와 `@image2` 아빠는 체형 첫 줄만 들어가며 CLOTH 절은 없다. 코타 250컷 SCENE에 황토/OCHRE/B98F52 언급 0회. 아빠는 감색/AZURE/3B5A72가 27컷에 있고 공통 앵커에도 아빠 옷 AZURE가 있으므로 둘 다 색상 지시가 완전히 없는 것은 아니다. 특히 코타 옷색을 텍스트로 고정하는 정보가 빠지는 구조다.
3. 회차 손님 `@image9`는 `_series-config.mjs` 등록부의 desc를 사용한다. 01권 두루미·07권 개구리의 실제 손님 시트 프롬프트에 `kota-cast.md`의 공통 Guest 의상 규격이 포함되지 않는다. 또한 그 원본 규격도 옷색을 GREEN/OCHRE/BURNT EARTH 중 하나로만 두어 종별로 고정하지 않는다. 따라서 손님 옷색 일관성을 보장할 텍스트 기준이 약하다.
4. `얼굴·비율·색은 시트와 100% 동일`과 `@imageN` 참조 지시는 존재한다. 참조 지시가 없는 문제가 아니라, 이미지 참조에만 의존하고 구체 의상 텍스트가 복사 과정에서 빠지는 문제다. 시트를 붙였어도 이번 색 변화의 단일 원인이라고 확정할 생성 로그는 없다.

## 추가 충돌과 전달 경로

- 앵커의 분홍은 코타 목 수건에만/손님에는 절대 금지라는 문구는 07권에서 자기 수건을 아기 손님에게 건네는 예외를 직접 표현하지 않는다. 색을 바꾸라는 뜻이 아니라 같은 수건이 이동하는 사건인데, 소유자 고정 표현이 혼선을 줄 수 있다.
- `copyText`는 텍스트만 복사한다. 실제 이미지 첨부 여부는 이번에 사용자에게 확인하지 않았고, 문제의 원인으로 가정하지 않는다.
- 자동 배치 `draw-changjak.mjs`는 캐릭터 시트 대신 완료 권의 p10 한 장을 참조한다. 사용자가 그 경로를 썼다는 뜻은 아니다.
- 배포된 `/kota-core.js`를 GET하여 로컬 파일과 개행 정규화 후 동일 확인했다. 새 코드가 배포되지 않아서만 생긴 현상이 아니다.

## 후속 수정 방향

수정 요청 시 시트의 현재 외형과 의상을 기준으로 페이지 복사 프롬프트에도 캐릭터별 의상 색·길이·수건·신발을 충분히 전달한다. 손님은 해당 시트에서 정한 옷색을 유지하도록 하고 임의 팔레트 선택을 막는다. 수건 전달·목욕 등 이야기상 예외를 구분한다. 옷색 문제를 팔레트 전체 변경이나 캐릭터 재설계로 해결하지 않는다.

이번에는 진단 문서만 추가했다. 제품 프롬프트/코드/등록 이미지는 변경하지 않았고 push도 하지 않았다.
