## 요청과 완료 조건

한글 블록 게임 상단 예시 단어도 실물·화면 블록과 같은 색 규칙으로 표시한다. 초성·받침은 주황색, 모음은 녹색이어야 하며 세로·가로 모음과 받침이 있는 음절에서도 조합 관계를 알아볼 수 있어야 한다.

## 읽은 기억과 변경 범위

[게임 MEMORY](../MEMORY.md), [블록 놀이 작업](20260921-blocks-analog-digital-hub.md), 루트·게임 기능 지침과 디자인 시스템을 확인했다. `KoreanBlockPlayer`, `TangoBoard`의 실물 블록 색상과 예시 단어 표시만 변경하며 인식·조합 로직은 건드리지 않는다.

## 결정과 진행

- 완성형 한글 글리프 내부에는 초성·중성별 CSS 색상을 줄 수 없으므로, 음절 모양을 유지하는 자모 격자 표시를 사용한다.
- 자음·받침은 화면 블록의 주황색, 모음은 화면 블록의 녹색 상수를 공유한다.
- 오른쪽 모음은 초성과 나란히, 아래 모음은 초성 아래에 놓고 받침은 마지막 줄에 둔다. 정답 타이핑 효과와 스크린리더용 완성 단어도 유지한다.

## 검증

- `ColoredHangulWord.test.tsx`와 기존 판 조합 테스트: 2파일 16개 통과. 초성·받침 주황색, 중성 녹색과 옆/아래 모음 배치를 확인했다.
- 클라이언트 `tsc --noEmit`과 Vite 프로덕션 빌드 통과.
- 로컬 Vite를 `DISABLE_PUBLISH_SCHEDULER=1`, 운영 API 읽기 전용 프록시로 실행하고 1680×1050에서 `나무`와 받침 단어 `집`을 확인했다. 색상은 각각 `rgb(240, 158, 92)`, `rgb(89, 184, 158)`이며 판·버튼과 겹치지 않았다.

## 후속 조형 개선 — 2026-09-21

사용자 실화면에서 자모를 별도 격자로 조립한 글자가 지나치게 벌어지고, 옆모음과 아래모음의 크기도 서로 어색하다는 피드백을 받았다. 자모마다 임의 크기와 칸을 주는 방식을 제거하고, `NanumSquareRound`의 완성형 음절 글리프를 두 겹으로 정확히 포갠 뒤 중성 위치만 녹색으로 잘라 보여 주도록 바꿨다. 이 방식은 원래 글자의 획·비율·자간을 그대로 유지하며 초성·받침 주황색과 중성 녹색 규칙도 지킨다.

- 옆모음/아래모음/복합모음과 받침 유무를 여섯 가지 레이아웃으로 나눠 녹색 영역을 제한한다.
- 음절 바깥 크기를 `0.9em`으로 통일하고 음절 사이 간격은 `0.025em`으로 줄였다.
- 부모 제목에 걸려 있던 큰 흰색 외곽선과 자간을 제거하고, 글리프 자체에 비례하는 외곽선과 그림자를 적용했다.
- 관련 컴포넌트·판 조합 테스트 19개와 클라이언트 타입 검사·프로덕션 빌드를 통과했다.
- 로컬 앱은 HTTP 200으로 응답했으나 이 세션의 인앱 브라우저가 localhost 탐색에서 시간 초과되어 새 렌더 화면 캡처는 완료하지 못했다.

## 배포 화면 반증과 두 번째 수정 — 2026-09-21

`1134f7959` 배포 뒤 사용자가 보낸 `바다` 화면에서 완성형 글리프를 직사각형으로 잘라 색칠한 방식의 결함을 확인했다. 분할선이 실제 자소 경계를 알 수 없어서 ㅂ과 ㄷ의 오른쪽 획 일부까지 모음 녹색으로 바뀌었다. 따라서 완성형 글리프 색상 레이어 방식을 폐기했다.

- 초성·중성·받침을 각각 독립 자모로 렌더링해 색 침범이 구조적으로 발생하지 않게 했다.
- 최초 격자 방식의 넓은 간격은 되돌리지 않고, 음절 폭을 `0.86em`으로 줄이고 자모 영역을 겹쳐 자연스럽게 붙였다.
- 옆모음·아래모음·복합모음에 별도 배치를 사용하고, 받침이 있으면 상단 자모를 함께 축소한다.
- 관련 컴포넌트·판 조합 테스트 19개와 클라이언트 타입 검사를 통과했다.

## 세 번째 간격 조정 — 2026-09-21

`c54c72fb6` 배포 뒤 사용자가 보낸 `오리` 화면에서 색 침범은 사라졌지만 ㄹ과 ㅣ, ㅇ과 ㅗ가 거의 맞닿은 것을 확인했다. 최초 격자처럼 크게 벌리지 않고, 옆모음은 `0.07em`, 아래모음은 `0.05em`만 더 떨어뜨렸다. 음절 바깥 폭·높이와 받침 위치도 같은 양만큼 늘려 잘리지 않게 했다.

- 관련 컴포넌트·판 조합 테스트 20개와 클라이언트 타입 검사·프로덕션 빌드를 통과했다.

## 반응형 글자 크기 확대 — 2026-09-21

`d3028a40f` 배포 뒤 2224×1246 화면에서 예시 단어 `코트`가 280px 삽화에 비해 작다는 피드백을 받았다. 상단 단어의 기준을 고정 크기로 키우지 않고 뷰포트 너비와 높이 중 작은 제한을 따르는 `clamp()`로 조정했다.

- 일반 배치: `clamp(3rem, min(15vw, 18vh), 13rem)` — 큰 태블릿에서는 약 224px, 667×375 모바일 가로에서는 약 68px.
- 카메라 가로 2열 배치: `clamp(2rem, min(8vw, 20vh), 9rem)` — 절반 폭 패널 안에서만 확대한다.
- 짧은 모바일 화면에서는 높이 기준이 먼저 걸려 판 영역을 침범하지 않는다.
