## 사용자 의도

Qwen으로 만든 인어공주 장면 선화를 기존 어휘 색칠 활동처럼 사용할 수 있는지 검토 요청. 처음에는 단순화 가능성을 언급했으나, 이어 현재 수준을 그대로 쓸 수 있으면 좋겠다고 명시했다. 따라서 그림을 먼저 단순화하지 않고 기존 그림의 활용 가능성을 우선 평가한다.

## 실제 코드

`ColoringPlayer.tsx`는 현재 탭 채움이 아니라 선택 색의 칸 안에서만 붓질하는 안내 색칠이다. 90% 채우면 나머지를 자동 완성한다. 일부 CLAUDE 설명은 이전 탭 방식이다. 선화 원본 해상도에서 shared `buildWalls`(기본 밝기 128)·`labelRegions`로 연결 영역을 만든다. `paintableRegions`는 전체 면적 0.3% 이상이며 테두리에 닿지 않는 칸만 고른다. 이후 `buildPalette`가 원본 삽화에서 색을 읽어 흰 칸을 추가 제외한다.

원본과 선화의 그림 사각형을 정렬하고 네 귀퉁이를 배경색으로 보는 `readColorSource`는 무지 배경의 낱말 이미지에 맞춘 가정이다. 장면에는 다른 색의 하늘·바다·산호가 귀퉁이를 차지하므로 그대로 적용하기 어렵다. 기존 512 정사각 변형 `auto-color.mjs` 수치를 실제 원본 해상도 플레이 수치로 보고하지 않았다.

## 세 장 실제 영역 분리

`D:/ComfyUI-output/qwen21-mermaid-test/audit-scene-regions.mts`에서 shared 소스를 직접 import, 원본 1376×768 PNG 픽셀에 기존 분리 규칙을 적용했다. 색 팔레트 단계 이전 수치이며 실제 브라우저/아이 플레이 검증은 아니다. 영역마다 임의 색을 입힌 진단 PNG를 육안 확인했다.

| 장면 | 전체 연결 영역 | 필수 후보 칸 | 후보 면적 | 테두리 연결 면적 |
|---|---:|---:|---:|---:|
| 밤바다 | 205 | 7 | 6.6% | 85.4% |
| 구출 | 241 | 12 | 15.2% | 75.7% |
| 정원 | 199 | 8 | 8.0% | 84.4% |

진단 이미지에서 정원의 얼굴과 조개 일부 등이 채워지지 않고 일부 다른 부분은 합쳐졌다. 테두리 연결 면적에는 정상 하늘/바다도 포함되므로 이 수치 전체를 누수율로 해석하지 않는다. 밝기 기준 180/220/245도 비교했지만 전체 문제는 해결되지 않았다. `region-audit.json`에 결과와 `region-audit-{night,rescue,garden}.png`에 진단을 저장했다.

## 판단과 다음 실험

### 사용자 정정 후 재확인

사용자가 기존 그룹핑과 실제 참조 도안 프롬프트를 다시 확인하도록 지시했다. 앞서 전체 연결 영역 199~241개를 아이가 하나씩 상대하는 것처럼 설명한 것은 부정확했다. `answer-colors.ts`의 `buildPalette`는 채널별 색 차이 40 미만인 칸을 같은 `regionIds` 그룹으로 묶는다. 플레이어는 그룹 전체에 힌트를 표시하고 같은 색에 속한 여러 칸을 한 붓질로 칠할 수 있다. 자동 마무리 90%는 개별 칸 기준이고, 그룹의 칸을 모두 끝내면 다음 색으로 자동 이동한다. 한 칸을 끝내면 떨어진 같은 색 칸 모두를 즉시 채우는 구현은 아니다.

작업판이 실제로 읽는 `public/coloring-plan-data.json.promptLine`과 `coloring-plan.html`의 `promptLineFor`를 확인했다. 프롬프트는 원본 위치·크기·각도 유지, 1024 기준 약 6px 균일한 검은 선, 틈 없는 폐곡선, 흰 내부, 6~12개 영역, 반복 비늘·점·작은 장식 제거, 테두리 안 단일 대상/배경 없음 등을 명시한다. 재시도 시 실패 유형별 보정 문구를 덧붙인다. 이전 Qwen 선화 프롬프트는 폐곡선·정량 선 굵기 요구가 부족하고 비늘 유지 지시가 있어 기존 게임용 규격과 달랐다.

따라서 다음 행동 우선순위를 수정한다. 새 마스크 구조를 먼저 구현하기보다 **기존 색 그룹핑을 그대로 활용하면서 기존 도안 프롬프트의 폐곡선·선 굵기·좌표 유지 규칙을 장면에 적용**해 한 장 시험한다. 단일 대상/배경 금지 및 6~12영역 규칙은 낱말용이므로 장면에 그대로 복제하지 않는다. 세부를 일괄 삭제하지 않고 보이는 디테일과 실제 칠할 영역을 구별해 검증한다. 아래 별도 마스크는 이 방식으로 해결되지 않을 경우의 후보로 낮춘다. 앞선 면적 수치는 팔레트 전 후보 검사이며 실제 색 그룹 수/플레이 난도를 측정한 값이 아니다.

현재 이미지를 무수정 기존 플레이어에 넣는 것은 부적합하다. 그러나 시각적 디테일을 버려야 한다는 증거도 아니다. **표시 선화와 내부 색칠 마스크를 분리**하는 장면 모드를 우선 제안한다. 선 틈을 닫고 큰 의미 영역을 묶는 내부 마스크를 만들고, 세부 장식은 자동으로 채우며 아이는 큰 면을 칠한다. 이는 아직 구현·검증하지 않은 제안이다.

장면 모드는 테두리 영역을 무조건 제외하지 말고 유효한 하늘/바다를 허용해야 한다. 원본 좌표 기반 색 추출을 쓰되 생성형 변환으로 바뀐 경계·생략물은 검수해야 한다. 보정이 실패한 장면만 큰 폐곡선·장식 축소 프롬프트로 재생성한다. 첫 실험은 비교적 후보 면적이 큰 구출 장면으로 하되, 다른 장면과 일반화하지 않는다. 실제 휴대폰에서 붓질·누수·완료·색 일치 확인 후 적용 여부를 결정한다.
