## 요청과 결론

학습 홈 V5에 긍정 피드백을 준 뒤 사용자가 전체 플랫폼 UI/UX·디자인 시스템을 살펴보라고 요청했다. 이어 '디자인 시스템 다시 만들어도 됨', '전체적으로 독후활동 게임이나 전부다 꼼꼼하게 확인해줘'라고 범위를 강화했다. [홈 논의](../../strategy/tasks/20261012-learner-home-direction.md)는 기존 기록에 보존한다.

게임에서 실제 진행을 막는 짧은 가로 화면 배치와 완료 결과 소실을 확인했다. 홈 개편과 함께 공용 탐색·학습판·결과 계약을 정리해야 한다. [디자인 시스템 v2](../../../design-system.md)를 다시 작성하고 [코드 안내](../../../../packages/client/src/design-system/README.md)의 낡은 토큰·컴포넌트 설명을 바로잡았다. 이는 구현 기준안이며 제품 적용 완료를 의미하지 않는다.

플랫폼 방향은 [PLATFORM.md](../../../PLATFORM.md)를 유지한다. 한글/영어 학습 중심 홈, 간결한 이어 하기, 추천 3권을 기준으로 삼는다. 모바일 탐색·세부 토큰·컴포넌트 동작은 이번 검토자의 구현 제안이며 사용자에게 이미 확정받은 세부사항으로 표현하지 않는다.

## 점검 방법과 증거 수준

저장소 인수인계·영역 BRIEF/MEMORY·CLAUDE·플랫폼 기준·현재 디자인 토큰/프리미티브를 읽고 라우터·대표 화면·공용 게임 플레이어와 호스트를 대조했다. games 등록 전체와 VocabularyStudyContent의 별도 dispatch를 대조했다. 파닉스 한글/영어/중국어 호스트와 활동 종류의 셸·진행·크기·접근성·완료 배선을 검토했다.

운영 웹의 기존 QA 프로필에서 동화·게임·학습·공개 활동지 대표 경로를 직접 조작했다. 375×812, 812×375, 1024×768, 1280×800의 브라우저 viewport를 사용했다. 입력은 QA 학습 이벤트를 남길 수 있다. 콘텐츠·계정 설정·외부 발행·예약 작업은 수정하지 않았다. 개인 프로필/기록은 보고서에 옮기지 않았다.

- **실행 확인**: 화면·DOM 크기·입력·상태 전환을 직접 관찰.
- **소스 확인**: 현재 배선·상태 처리·스타일에서 확인. 실패를 강제해 재현하지 않은 경우 별도 표기.
- **설계 제안**: 다음 구현의 방향. 실행된 코드와 구분.
- **미검증**: 음성 내용/겹침의 실제 청취, 모든 책/언어/단원, 실물 카메라·Bluetooth 필기, iOS/Android 실기기, 보호된 내부 관리 화면의 실제 조작.

실제 소리를 청취·기록하지 않았으므로 음원 품질·나레이션 무중단을 통과로 보고하지 않는다. 음성 콜백 뒤의 화면 이동만 관찰했다. 그림책 1,000권 전수 플레이도 하지 않았다. 전체 유형의 구조 검토와 아래 대표 실행 범위를 완료한 보고서다.

git fetch 후 origin/main 대비 현재 HEAD는 0 behind / 8 ahead였다. 기존 브랜치·미커밋 자료를 통합/삭제하지 않았다. 관련 파일의 git log --all과 codex/learning-report diff를 확인했다. 과거 268122f42는 공개 활동지의 숨은그림 결과 overlay를 보완한 작업이며 이번 독후게임 호스트의 자동 닫기와 다른 호출부다. learning-report의 같은 플레이어에는 해당 배치/완료 수정이 없었다. 다른 모든 브랜치의 전수 diff를 했다는 뜻은 아니다.

## P1 — 게임 진행·완료

### 1. 이야기/사물 장면 찾기의 보기 소실

**실행 확인.** 신데렐라의 독후활동 → 이야기 찾기/사물 장면 찾기. 812×375에서 이야기 찾기 두 번째 문제의 보기 컨테이너 높이 약 **10px**, 사물 장면 찾기는 **0px**였다. 선택 그림을 사실상 볼 수 없었다. 1024×768에서도 보기가 일부 가려져 내부 세로 스크롤이 필요했다.

[StoryImagePlayer](../../../../packages/client/src/features/games/components/players/StoryImagePlayer.tsx)의 전체 화면 flex 안에 진행·문제·재생 버튼·문제 그림·자막을 쌓고 보기만 flex-1/min-h-0로 줄인다. overflow-hidden과 내부 스크롤 때문에 문서 전체에 overflow가 없어도 게임은 잘린다. 한국어/영어 이야기 찾기와 한국어 사물 찾기가 같은 플레이어를 사용한다.

**후속:** 높이 기준 배치와 학습판 최소 공간을 정의한다. 짧은 가로 화면에는 문제/도구를 옆으로 옮기고 전체 보기를 식별할 수 있도록 만든다. 테스트는 선택지 rect와 부모 clipping을 확인한다.

### 2. 완료 직후 결과·다시 하기 소실

**실행 확인.** 쪽 순서 게임에서 오답 표시 후 4장을 순서대로 배치해 진행 4/4에 도달했다. 마지막 처리 뒤 목록으로 돌아가 결과·재시도를 사용할 수 없었다. 숨은그림도 한 장면의 구두·시계·마차·성·계단 5개를 모두 찾아 0개 남음 뒤 같은 복귀가 발생했다.

[PageOrderPlayer](../../../../packages/client/src/features/games/components/players/PageOrderPlayer.tsx)는 finish에서 setFinished와 onComplete를 함께 호출한다. [HiddenObjectPlayer](../../../../packages/client/src/features/games/components/players/HiddenObjectPlayer.tsx)와 StoryImagePlayer는 finished effect에서 onComplete를 호출한다. 상위 [VocabularyStudyContent](../../../../packages/client/src/features/vocabulary-unit/components/VocabularyStudyContent.tsx)의 handleGameComplete는 activeGame을 null로 바꿔 플레이어를 닫는다.

이야기/사물 찾기의 같은 결과 소실은 **소스 확인**, 마지막 라운드까지 실행한 증거는 아니다. 한글/영어/다국어 쓰기는 별도 결과 컴포넌트 없이 완료 콜백으로 돌아가는 구조이며 의도 여부를 구분해 공통 경험을 정해야 한다.

공개 /activity의 HiddenObjectPanel은 onComplete에서 finished만 기록해 결과를 유지한다. 따라서 '숨은그림은 모든 경로에서 결과가 사라진다'고 일반화하지 않는다. 그림짝과 블록에서 결과가 남는 정상 흐름도 확인했다.

**후속:** 완료 기록과 닫기를 분리한다. 결과를 남긴 뒤 다시 하기/명시적 복귀를 제공한다. 마지막 음성/칭찬·이중 완료·재시작 초기화를 함께 검증한다.

### 3. 영어 블록의 문제/슬롯 잘림

**실행 확인.** 영어 블록의 castle에서 c,a,s,t,l,e를 눌러 한 문제 정답 및 진행 1/3을 확인했다. 1024×768에는 6개 조합 슬롯이 5+1로 줄바꿈됐다. 812×375에서는 알파벳 26개 트레이가 세 줄로 공간을 차지하고 문제·그림·슬롯·다음 영역이 얇은 띠 안에 가려졌다.

[EnglishBlockPlayer](../../../../packages/client/src/features/games/components/players/EnglishBlockPlayer.tsx)는 전체 화면 overflow-hidden과 shrink-0 트레이, 큰 최소 그림 높이/슬롯을 함께 사용한다. 글자 버튼을 누를 수 있어도 목표를 확인하기 어려워 조합 진행이 막힌다.

**후속:** 단어·슬롯을 우선 확보하고 트레이를 높이·입력 목적에 맞게 배치한다. Book 1의 글자 학습을 낱말 철자 학습으로 바꾸지 않는다. 긴 단어의 슬롯 순서를 확인한다.

## 과정 활동·교구 점검 범위

한글 첫 모음 듣기는 375px에서 아를 누른 뒤 다음 야가 활성화됨을 확인했다. 영어 Book1 A/B/C 배우기는 375px에서 글자 탭·그림·단계 화면을 확인했다. 전체 활동/단원 완료·복습 세트 완주를 했다는 뜻은 아니다.

소스 검토 대상은 모음 듣기/쓰기, 자음 듣기·조합/쓰기, 음절 선택, 글자 사냥, 복습 쓰기/뒤집기, 듣고 고르기, 영어 알파벳 배우기/쓰기, CVC 패턴 배우기/쓰기, word-family 배우기, 병음 성조 줄/선택, 찬트다. 해당 호스트의 직접 게임 배선·data gate·완료 기록·복습 카드 수/초점도 대조했다.

ActivityShell은 44px 돌아가기와 오른쪽 탭 가로 스크롤을 이미 제공한다. 모음 듣기의 단계 잠금·학습 대상과 UI 언어 분리, 복습4쌍·안정적 shuffle은 유지할 가치가 있다. vw/vh 타일 규칙은 존재하지만 쓰기/문제 그림 등 고정 최소 높이는 짧은 화면에서 별도 확인이 필요하다. 소스 위험을 모든 활동의 재현 오류로 분류하지 않았다.

찬트는 autoplay 실패 시 큰 재생 버튼으로 폴백하고 한 곡 ended/직접 완료를 기록하며 자동 복귀하지 않는 소스다. 이는 점수 게임과 다른 완료 계약이다. 카메라/노트는 인수인계·상태 소스만 검토했고 권한·실물 입력은 실행하지 않았다.

## 디자인 시스템의 실제 차이

기존 문서에는 준비 중 사이드바, hero 배너, 카테고리9권/3행, 표지 아래 제목, rounded-xl=12px, 폰트 CDN @import 등이 남아 있었다. 현재 carousel·표지 제목 오버레이·활성 메뉴·@font-face·실제 radius와 맞지 않는다. 코드 README의 coral-50/900 미정의·mint 누락도 정정했다.

현재 토큰은 재사용되지만 CSS 변수·폰트 정의가 별도로 남아 있다. typography.ts는 패밀리만 제공하며 역할별 크기/줄간격은 없다. 공용 Button/Chip과 각 화면 자체 버튼이 함께 존재해 크기·대비·상태 계약이 달라진다.

v2는 cream/white/ink 중심, 브랜드 포인트, 역할별 밀도, 의미 토큰 제안, 큰 조작 영역, 게임 학습판·결과 규칙을 정의했다. 카드/그림을 전부 같은 스타일로 바꾸거나 작품 그림체를 획일화하지 않는다. 쓰기99%·색칠90%·채점용 폰트는 유지한다.

## 유지할 요소

- 실제 표지·현재 읽기 언어 제목과 작품별 그림체.
- 언어·자산 조건에 따라 제공 가능한 게임만 노출하는 구조.
- 테스트한 유형의 즉시 정답/오답 표시, 블록 회전·undo·이야기 리빌.
- 유지되는 결과 화면·다시 하기의 정상 사례.
- 기본 reduced-motion·safe inset·loading gate와 건너뛰기.
- 공개 활동지의 온라인/인쇄 구분, 마케팅의 제한된 별도 테마.
- 학습 기록과 실제 습득의 구분, 기존 채점 기준.
