## 요청과 완료 조건

사용자는 기능별 기억과 담당 지침을 유지하고, 새 대화에서도 계속 이어서 작업하는 경험을 요청했다. 승인된 12개 영역 운영안을 적용한다.

## 결정과 진행

- 12개 BRIEF/MEMORY와 task 디렉터리, 공통 템플릿 및 기능 지도 생성.
- 기존 14개 전문 에이전트는 유지하고 관련 기억을 읽도록 연결. 부족한 개발 역할은 BRIEF로 제공하며 별도 런타임 에이전트를 등록한 것은 아니다.
- 300개 과거 메모리 파일명을 분야별 검색 후보로 분류. 본문 전체를 이관한 것은 아니다.
- 카메라 흰 판 작업은 실제 결과와 미해결 입력을 paused task로 이관.
- AGENTS.md·CLAUDE.md에서 기능별 기록을 먼저 읽도록 연결. 막연한 시작 요청에만 선택형 질문을 제공한다.
- marketing-specialist의 과거 포지셔닝과 문서 우선순위를 현재 STRATEGY 기준으로 정정.
- work-status.mjs는 모든 worktree의 기록을 읽기 전용으로 조회. 복사된 task를 브랜치 실행 상태와 혼동하지 않도록 메타데이터를 함께 출력.

## 검증

12개 영역에 client 40개 기능 폴더와 기존 14개 에이전트가 누락 없이 매핑됐고 과거 메모리 300개가 검색 목록에 포함됨을 확인했다. Markdown의 로컬 링크를 검사했다.
node --check, 전체 worktree JSON 조회, 현재 worktree 한정 조회, 하위 디렉터리 실행, 잘못된 옵션 거부를 확인했다.
이관 시 조회된 worktree는 46개이며 옛 폴더 45개는 task 기록이 없어 미이관/미확인이다. 이를 작업이 없다는 뜻으로 해석하지 않는다.

카메라 재개 경로는 AGENTS → 작업 지도 → camera BRIEF/MEMORY → 흰 판 task → 상세 프레임 기록으로 연결됨을 확인했다. 별도 새 대화의 자동 행동이나 인식 엔진 자체를 이번 작업에서 재검증한 것은 아니다.
