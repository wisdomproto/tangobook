# 실물 블록 카메라 = 파닉스 블록게임의 한 모드 (설계)

2026-09-17. 사용자 지시 두 줄이 출발점이다.

> 「지금 한글, 영어 블록 인식하는거 만들어놨자나. 이거 게임 방식을 한글, 영어 파닉스 블록게임이랑
>  똑같이 하면됨. 한글, 영어 컨텐츠 안에 있는 블록게임.」
> 「카메라가 테블릿 세로로 있을수도 있고 가로로 있을수도 있어. 적응형으로 만들어보자.」

## 1. 무엇이 문제인가

낱말 소스는 **이미 같다**(파닉스 단원의 `phonicsConfig.targetWords` + `flashcards[].imageUrl`).
갈라지는 건 게임 껍데기다.

| | 앱 블록게임 (`KoreanBlockPlayer`) | 카메라 화면 (`tango-board-3d.html`) |
|---|---|---|
| 문제 | 그 단원 낱말 4개 | 전 단원에서 아무거나 1장씩 무한 |
| 진행·점수 | `2/4` + 결과 화면 | 누적 점수만 |
| 정답 뒤 | 낱말 → 칭찬 → 장면 리빌 → 다음 | 낱말 → 칭찬 → 「다른 낱말」 버튼 |
| 장면 리빌 | 돈다 | **죽어 있다** — `pickWord` 가 `page: null` 고정 |
| 학습 기록 | `logGame` | 없음 |
| 자산 프리로드 | `PhonicsGameGate` | 없음 |
| 진입 | 단원 활동 타일 | 저작도구 TopBar 링크뿐 |

즉 **카메라 쪽에 게임이 없다.** 앱 쪽에 이미 다 있으므로 옮길 것은 인식기 하나다.

## 2. 결정된 것 (사용자)

1. **앱(React)으로 들인다.** HTML 에 게임 껍데기를 다시 짜면 위 표를 두 벌 만들게 된다.
2. **진입 = 기존 블록게임 안 「📷 실물 블록」 토글.** 타일은 지금대로 「🧩 블록 게임」 하나.
3. **적응형 = 화면 배치만.** 거울·거치대는 고정이므로 인식기의 방향 상수는 건드리지 않는다.
4. **📤 보내기는 남긴다** — 디버깅용(사용자: 「지금 테스트 중이니까」).

## 3. 부품 — 인식기를 떼어낸다

`packages/client/public/tango-reco.js` · 고전 스크립트 한 파일 · 자기 상태를 소유한다.

```js
TangoReco.load({ set:'ko'|'en', onProgress })   // opencv.js + 형판 json
TangoReco.read(rgba, W, H)  →  { word, items, cell, info, masks }
TangoReco.tune(patch)                           // 방향 노브(rot) 등
```

옮기는 범위 ≈ 2,800줄: 자모 조합(`parseFree`·`parseGroup`·`composeHangul`) · 형판
(`buildLegoTemplates`·`loadSticker`) · 칸 스윕(`legoCellSweep`) · 펴기(`legoRectify`) ·
판 껍질(`legoPlateHullMask`) · 쪼개기(`splitLego*`·`peelLego`) · 형판 맞추기
(`matchLegoShape`·`matchSticker`) · 스티커 경로(`readSticker`·`stickerMask`) ·
그 위 진입점 `recognizeLegoDirect`.

🔴 **사본을 만들지 않는다.** `tango-board-3d.html` 은 자기 복사본을 **지우고** 이 파일을 부른다.
두 벌이 되면 한쪽만 고치는 사고가 나고, 실험실(📤·마스크 미리보기·슬라이더)이 배포본과
다른 코드를 재게 된다 — 그러면 거기서 잰 어떤 숫자도 결론이 아니다.

🔴 **다시 쓰지 않고 옮긴다.** 고쳐 쓰고 싶은 곳이 보여도 이번엔 손대지 않는다. 옮기기와 고치기가
한 커밋에 섞이면 나빠진 지점을 못 찾는다.

🔴 **획 블록 경로도 같이 옮긴다.** `recognizeLegoDirect` 가 스티커/획을 첫 프레임에 공짜로
가르므로 진입점이 하나다. 갈라내려 들면 그 판정을 두 번 만들게 된다.

## 4. 픽셀 받는 길 — GL 을 버린다

```
지금  video → 캔버스(좌우 되돌림) → WebGL simTex → grabDetect: blit → readPixels → detBuf
앞으로 video → 2D 캔버스(긴 변 1440, 좌우 되돌림) → getImageData → read()
```

앱에는 3D 렌더가 없으니 GL 이 할 일이 없다. 해상도는 지금과 같은 `TUNE.detW = 1440`(긴 변 기준 —
세로 화면에서 가로만 고정하면 화소가 폭발한다).

🔴 **위아래 한 번을 갚아야 한다.** `readPixels` 가 아래부터 읽어 주는 것을 전제로 인식기가
`TUNE.legoFlip = 9`(안 뒤집음)로 맞춰져 있다. 2D 캔버스는 위부터 주므로 그대로 넘기면
**좌우 대칭인 글자(ㄷ·ㅁ)는 멀쩡한데 ㅗ↔ㅜ·ㅏ↔ㅓ 만 뒤집힌다**. 「다·더는 되는데 도·두만
안 된다」가 정확히 이 증상이고, 2026-08 에 한 번 겪었다. §3 의 13장 대조가 이것도 잡는다.

🔴 **좌우 되돌림은 입구에서 한 번만.** 경로마다 뚝뚝 떨어뜨리면 프레임마다 방향이 달라 보인다.

⚠️ **올라온 JPEG 으로 한 테스트는 실시간을 대신하지 못한다** — 그 그림은 이미 한 번 좌우가
뒤집힌 사본이다. 하네스는 먼저 뒤집어 놓고 잰다.

## 5. 게임 — 판만 갈아 끼운다

`KoreanBlockPlayer` 가 보는 것은 `composedSyllables: string[]` 한 줄뿐이다. 그 줄의 출처만 바꾼다.

| | 화면 판 | 실물 판 |
|---|---|---|
| 입력 | `parseBoard(toItems(placed))` | `useBoardCamera()` — 5프레임 다수결 |
| 문제 4개 · 새 음절만 읽기 · 자동 정답 · 낱말→칭찬 · 장면 리빌 · 결과 · `logGame` | 그대로 | **그대로** |

영어는 인식 낱말을 글자별로 `grid[i]` 에 꽂으면 `EnglishBlockPlayer` 가 그대로 굴러간다.

새로 짜는 것은 **`useBoardCamera` 훅 하나**다: getUserMedia(전면·1280×720·15fps) → 250ms 마다
프레임 → `TangoReco.read` → 다수결 → `{ syllables, info, sendFrame() }`.

- 되돌리기/지우기 버튼은 실물에선 지울 게 없으니 숨긴다.
- 오답 상태를 따로 만들지 않는다 — 아이는 블록을 옮기면 되고, 화면은 읽은 것을 보여 주면 된다.
- 🔴 다수결 5프레임(1.25초)을 **더 줄이지 않는다** — 사용자가 「이정도가 좋다」고 했다.
  더 낮추면 중간 낱말을 지껄인다.
- 🔴 iOS 는 요소마다 오디오를 잠근다 — 소리는 `lib/audio-unlock` 을 쓰는 기존 경로 그대로 탄다.

## 6. 적응형 배치

- 🔴 **실물 모드에선 `MobileLandscapeGate` 를 안 씌운다.** 「가로로 돌려주세요」 벽이 곧 적응형의
  반대다. 화면 판 모드는 지금대로 둔다(조각을 끌어 놓아야 해서 가로가 필요하다).
- **세로**: 삽화 → 낱말 → 읽은 낱말, 한 줄
- **가로**: 삽화 ‖ (낱말 + 읽은 낱말), 두 칸
- 판이 화면에 없어 배치가 카드 하나뿐이라 둘 다 쉽다. 분기는 `aspect` 한 줄.
- 🔴 실측은 뷰포트가 아니라 **그 칸의 `clientWidth`** 로. 375px 뷰포트는 패딩 빼면 343px 이다.

⚠️ 거치가 고정이라는 전제 위의 설계다. 혹시 가로에서 그림이 돌아 들어오면 `?rot=` 노브로
눈으로 확인한다 — 자동 판정은 안 넣는다(첫 프레임에 방향을 못 정하면 잠겨 헤맨다).

## 7. opencv.js 11MB — 진짜 진행률

지금 HTML 의 `#cvLoad` 는 막대가 좌우로 왕복만 하는 **가짜 진행률**이다(`@keyframes cvslide`).
태블릿 LTE 로 수십 초인데 얼마나 남았는지 말해 주지 않으면 아이에겐 멈춘 것과 같다.

- 받는 곳이 이미 jsDelivr(`@techstark/opencv-js@4.11.0-release.1`)이고 **CORS 를 열어 준다** —
  그래서 `fetch()` 가 되고, `content-length` 도 온다. `r.body.getReader()` 로 바이트를 세면
  0→100% 가 실수치로 나온다. 앱에 있는 `GameLoadingGate`(코랄 바 + % 숫자)에 그대로 꽂는다.
- 🔴 **이 게이트엔 「건너뛰기」를 달지 않는다.** opencv 없이 넘어가면 인식이 아예 안 되는
  화면으로 들어간다. `GameLoadingGate` 에 `skippable` 를 하나 받게 고친다(자산 프리로드 쪽은
  건너뛰기 유지 — 거기선 넘어가도 게임이 돌아간다).
- 두 번째부터는 안 뜬다 — Cache Storage(`tango-cv-v1`) + jsDelivr `immutable` 1년.
  게이트도 250ms 안에 준비되면 안 그려진다.

## 11. 실제로 한 것 (2026-09-17 저녁 · `main` 6c09e802)

설계대로 갔고, **네 군데가 틀렸다.** 틀린 것만 적는다 — 맞은 것은 위 본문 그대로다.

### ① 방향: 「180° 회전」이 틀렸다 (§4)

본문에 「좌우 되돌림 + readPixels 상하 = 180° 회전」이라고 **유도**해 뒀는데 아니었다.
그대로 넣었더니 증상이 §4 가 예고한 그것이었다 — **카드 수는 다 맞는데(18·17·4·2·4·5·3·9·9)
글자만 전부 틀림**, 낱말이 `달비뮤쟝` → `다티킘뱌엉`.

같은 프레임을 실험실과 앱에 넣고 (좌우 O/X) × (0·90·180·270) 여덟을 구워 맞춘 답은
**거울 한 번, 회전 없음**이다. `getImageData`(위부터)와 `readPixels`(아래부터)의 차이가
텍스처를 안 뒤집고 올리는 것과 상쇄되어, 남는 건 거울뿐이었다.

🔴 **교훈은 §4 에 이미 적혀 있던 것보다 강하다: 방향은 유도하지 말고 재라.**

### ② 비율: 우리가 프레임을 자르고 있었다 (§2 에 없던 것)

`getUserMedia` 에 `width:1280` 과 `height:720` 을 **같이** 걸고 있어서 크롬이 비율까지 맞추려고
`resizeMode:'crop-and-scale'` 을 붙였다 — 세로 1212×2160 이 **1212×720** 으로 들어와 카드 4장 중
2장이 사라졌다. 사용자가 「기기마다 해상도도 비율도 다를 건데」라고 짚어서 재다가 나왔다.
→ **짧은 변만 요구하고 비율은 기기에 맡긴다.** 해상도는 계속 요구한다(버리면 640×480).

### ③ 해상도는 처음부터 문제가 아니었다

짧은 변 **240 → 2400px(10배)** 를 네 프레임에 훑어 **낱말이 한 글자도 안 달라졌다.**
`detW` 정규화 + 칸 배수·넓이 비율·장면 중앙값 관문이 실제로 일한다. 기하에 절대 픽셀은 없었다.

### ④ 판이 잘릴 때: 껍질을 넓히는 건 답이 아니었다 (§9 에 없던 것)

「판 껍질이 화면 가장자리를 따라 서서 카드를 썬다」는 가설로 노브를 달아 0·2·4% 로 훑었는데
**결과가 한 글자도 안 달라졌다.** 좌우가 잘리면 그 자리 카드도 같이 잘려서 정보가 아예 없다.
노브를 걷어내고 **「블록 N개가 화면 끝에 걸렸어요」** 로 갔다.

그 과정에서 더 큰 것을 봤다 — **아무것도 안 자른 원본에서 이미 판이 좌우 화면 끝에 닿아 있다**
(`판끝 [위0 아래0 왼0.47 오0.62]`). 카메라가 판 폭을 다 못 본다. **거치 거리·각도 문제라 코드로
못 고친다** — 좌우는 5% 만 잘려도 무너지고 위아래는 30% 까지 버티는 이유가 이것이다.
