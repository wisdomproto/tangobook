## Git와 운영 환경

- `git add -A` 때문에 다른 작업의 파일 1,033개를 stage/커밋한 과거 사고가 있다. 파일별 stage와 실제 Git root/branch 확인이 필요하다.
- 워크트리가 사라져도 상위 저장소에서 Git 명령이 성공할 수 있다. `git status` 성공만으로 올바른 저장소라고 판단하지 않는다.
- 로컬 main과 현재 루트는 원격 main보다 오래됐을 수 있다. 보드 작업은 2026-09-21 `board-white-plate` worktree에서 수행했다.
- 2026-09-17 정리에서 사용하지 않는 로컬 브랜치 24개를 `refs/archive/codex-cleanup-20260917/`에 보관했다. 복구 목록은 공통 Git 디렉터리의 `codex-branch-cleanup-20260917/`에 있다. 이후 상태는 재확인한다.
- 2026-09-21 루트를 main으로 전환하고, 최근 30일간 Git 사용 기록이 없고 checkout되지 않은 로컬 브랜치 35개를 보관 후 삭제했다(51개 남음). 복구 참조는 `refs/archive/codex-cleanup-20260921/`, 기록은 공통 Git 디렉터리의 `codex-main-migration-20260921/REPORT.md`다. 루트의 이전 미커밋 변경과 미추적 파일 1,032개는 같은 참조 아래 `root-wip`에 보관했으며 main에 덮어씌우지 않았다. 옛 main 작업 폴더는 기존 파일을 유지한 채 detached 상태로 남겼다.
- 로컬 서버에서 `DISABLE_PUBLISH_SCHEDULER=1` 없이 운영 자격증명을 읽으면 예약 게시가 실제 실행될 수 있다. 코드의 옵션 처리와 시작 로그를 확인한다.
- R2/Supabase는 로컬 개발 서버에서도 운영 데이터를 가리킬 수 있다. 테스트라고 임의 저장·삭제·시딩하지 않는다.

## 검증에서 반복된 함정

- 비교 대상 버전·입력·실행 경로를 먼저 기록한다. 다른 코드/해상도/상태를 재고 같은 제품 결과로 보고하지 않는다.
- 화면의 `0`은 실제 측정 0인지 미갱신 값인지 대입부를 확인한다. 오래된 보드 디버그의 `점 0`이 대표 사례다.

- iOS는 실제 재생할 Audio 요소를 사용자 제스처에서 해금해야 한다. 기존 `lib/audio-unlock.ts`와 요소 재사용을 유지한다. 로딩이 끝났다는 사실은 재생 허가의 증거가 아니다.
- 첫 화면 성능은 JS entry 하나가 아니라 HTML이 요청하는 preload·CSS 등을 함께 측정한다. 엔트리 크기만 줄인 청크 분할이 전체 전송량을 늘린 전례가 있다.
