# 중국어 병음(拼音) 파닉스 타당성 조사

> 2026-08-06 · **조사 리포트**(빌드 아님). "만들 수 있는가 / 어떻게 만드나 / 무엇이 걸림돌인가"만 판단.
> 코드 미변경. 결정표(§6)는 착수 전 사람과 합의 항목.
> 1차 자료 = 사용자 제공 `중국어발음표.xlsx`(병음표) + `중국어+발음mp3(2).zip`(발음 mp3). 둘 다 실측 반영.

## 0. 한 줄 결론

**만들 수 있고, 지금까지의 새 언어 후보 중 코드 재사용률이 가장 높다.** 병음은 성모(声母)+운모(韵母)를
음절로 **블렌딩**하는 진짜 파닉스라 **영어 CVC·한글 자음+모음 합치기 활동이 거의 그대로 물려간다**
(가나처럼 blend 를 뺄 필요가 없다). 게다가 언어 인프라 3종이 **이미 다 깔려 있다** — `zh`(中文简体)가
`SUPPORTED_LANGUAGES` 에 등록됐고, Noto Sans SC + ZCOOL KuaiLe 폰트가 `index.css` 에 있고, **성조까지
정확한 Google Cloud TTS `cmn-CN-Chirp3-HD-Leda` 보이스가 낱단어 전사 0.83~0.98 로 검증돼 이미 쓰이는 중**
(다국어 어휘 게임). 새 축은 **성조(声调) 하나뿐**이고, 그마저 베트남어(vi)가 성조 글자를 NFC 로 다루는
선례가 있다.

**진짜 미결정은 코드가 아니라 두 가지 콘텐츠 결정이다**: ① **한자(汉字)를 노출할 것인가**(병음+그림만 vs
한자 병기) ② **성조를 4~5세에게 어디까지 가르칠 것인가**. 이 둘이 커리큘럼과 활동을 가른다.

## 1. 1차 자료 실측 — 병음표 xlsx + 발음 mp3 zip

### 1.1 `중국어발음표.xlsx` — 커리큘럼 유닛 분할의 1차 근거

4개 시트. 인코딩이 cp949 라 한글 라벨은 깨져 보이나 병음 데이터는 온전하다.

| 시트 | 내용 | 쓸모 |
| --- | --- | --- |
| 0 (조합표) | 성모 × 운모 격자 + **철자 규칙 주석** | 어떤 음절이 실재하는지 + y/w/ü 변환 규칙(아래) |
| 1 (발음표) | **운모(행) × 성모(열)** 유효 음절 격자 | 커리큘럼 음절 인벤토리의 정본 |
| 2 (발음표+한글) | 같은 격자에 **각 음절 한글 발음 표기**(마, 파, 타, 짜…) | 🔴 **L2 한국 아이용 발음 힌트의 완성된 원천** — 성모/운모별 한글 근사음이 이미 채워져 있다 |

xlsx 에서 확정한 인벤토리:

- **성모 23**: b p m f · d t n l · g k h · j q x · zh ch sh r · z c s · y w
- **단운모 6**: a o e i u ü
- **복운모/특수**: ai ei ui · ao ou iu · ie üe · er
- **비운모 9**: an en in un ün(前) · ang eng ing ong(後)
- **철자 규칙**(시트 0 주석 = 앱에서 표기/음원 키를 만들 때 반드시 지킬 것):
  - `i-` 시작 운모는 성모 없으면 `y-` (ia→ya, ie→ye, iong→yong), 단독 i→yi, in→yin, ing→ying
  - `u-` 시작은 성모 없으면 `w-` (ua→wa, uo→wo, uan→wan), 단독 u→wu
  - `ü-` 는 단독/무성모면 `yu-` (ü→yu, üe→yue, üan→yuan, ün→yun)
  - **j·q·x + ü → u 로 표기**(ju=jü, que=qüe, xuan=xüan) · 단 **n·l + ü 는 ü 유지**(nü, lü, nüe, lüe)
  - **축약**: iou→iu(niu), uei→ui(dui), uen→un(tun) — 성모와 결합 시 가운데 모음이 빠진다
  - 🔴 이 규칙들은 **성조 표기 위치**와 함께 병음 렌더링의 핵심이다(§2).

### 1.2 `중국어+발음mp3(2).zip` — 부분 음원 라이브러리 (실측)

- **796 파일 / 202 기본 음절**, 명명 = `{음절}{성조번호}.mp3` (na1·na2·na3·na4 = mā má mǎ mà 대응, 성조번호식).
  ü 는 괄호 표기: `nu(1).mp3` = nǖ. → **성조가 파일명에 이미 숫자로 인코딩**돼 있어 오디오 키 스킴
  `{syllable}{tone}` 로 그대로 쓸 수 있다.
- 🔴 **파일명의 `(2)` 그대로, 이건 세트의 "2편"이다** — 커버리지가 **성모 n~z 절반뿐**이다.
  - 있음: n o(감탄사 ō만) p q r s sh t x **y w** z zh (+ 이들의 성조 4개씩)
  - **없음: a e b m f d l g k h j c ch** (즉 성모 a~m 절반 = **part 1 미제공**)
  - 🔴 **가장 기본 교습 음절이 없는 쪽에 몰려 있다** — bà(爸)·mā(妈)·dà(大)·gē(哥)·kā·lā 전부 0.
    zero-initial(y/w) 음절(yi wu yu ya wo wei yuan yue yun)은 있어 整体认读音节 일부는 커버되나,
    **초급 커리큘럼을 이 zip 만으로는 못 채운다.**

**결론**: zip 은 "바로 쓸 수 있는 자산"이 **절반만** 맞다. 나머지 절반(a~m)이 없고, 성우·톤도 알 수 없다.
→ **음원의 정답은 zip 이 아니라 이미 검증된 Google Cloud TTS**(§3). zip 은 파일럿 비교·백업용.

## 2. 🔴 성조(声调) — 병음에만 있는 새 축

한글·영어엔 없던 축이고, 이 조사의 핵심 설계 포인트다. 병음은 **같은 음절이 성조로 뜻이 갈린다**:
`mā 妈(엄마) · má 麻(삼) · mǎ 马(말) · mà 骂(꾸짖다)`. 성조는 4성 + 경성(轻声, 무표기).
근거: 성조는 운모(음절핵)에 얹는 결합 diacritic(ā á ǎ à), 표기 규칙은 `a>e>o>i>u>ü` 순위, `iu/ui`
는 뒤 모음에 — [Wikipedia *Pinyin* → Tones/Placement](https://en.wikipedia.org/wiki/Pinyin).

### 2.1 세 층위에서 성조를 어떻게 다루나

| 층위 | 처리 | 선례 |
| --- | --- | --- |
| **글자(표기)** | 성조 부호는 대부분 **Unicode 유니코드 정합자**(ā=U+0101, ǎ=U+01CE…)로 존재 → NFC 로 단일 글자. `splitUnits` 가 vi 성조 글자(è, ố)를 이미 이렇게 유지한다 | vi (`split-units.ts` NFC 주석) |
| **음원(키)** | 오디오 키 = `{무성조 음절}{성조 1-4}` (zip 명명 그대로: `ma3`). 성조가 URL 에 박히므로 라이브러리 직행이 깔끔 | zip 명명 규칙 |
| **활동(학습)** | 🔴 **여기가 진짜 새 활동** — "같은 mā/má/mǎ/mà 를 소리로 구별"은 한/영/일에 없다 | **신규 설계 필요** |

### 2.2 성조를 타일·splitUnits 에 넣는 법

- **표시·블록·쓰기 게임**: 병음 음절을 **NFC 성조 글자로** 두면 `splitUnits(word, 'zh')` 가 코드포인트
  단위로 쪼갠다. `mā` 는 이미 정합자 1글자라 타일 하나. 단 `zh` 는 현재 splitUnits 에서 **한자 1자=1유닛**
  으로 처리(코드포인트) — 병음 라틴 문자열엔 그대로 맞지만, **병음은 별도 lang 축(`zh-pinyin` 개념)이
  필요할 수 있다**(한자 유닛과 병음 유닛이 다른 게임을 타므로). 착수 시 결정.
- **성조 부호를 못 붙이는 조합**(ǘ ǚ 위 캐럿 등)은 **성조번호 폴백**(`nu:3` → `nǚ`) — zip 이 이미 그렇게 한다.

### 2.3 성조 전용 활동 후보 (신규)

기존 활동으로 못 덮는 유일한 부분. 벤치마크 = 중국 유아 성조 학습("四声歌"·손동작 성조).

- **성조 듣고 고르기** — 소리(mā) → 성조 부호 4개(◌̄ ◌́ ◌̌ ◌̀) 또는 4성 카드 중 고르기.
  `WordListenChooseActivity`(듣고 고르기)의 보기만 "성조 4종"으로 바꾸면 **같은 컴포넌트 재사용** 가능.
- **성조 그리기/따라** — 성조 곡선(1성 평평·2성 상승·3성 V·4성 하강)을 손가락으로. 손동작 성조가 원형.
  `LetterFillCanvas` 계열이 아니라 **가벼운 곡선 트레이스** 신규(작은 컴포넌트).

🔴 **성조 범위도 결정 항목**(§6 #3): 4성 전부 vs 1·4성부터. 4~5세 변별 난이도는 **2성↔3성 구분이 가장
어렵다**(성인 L2 도)는 게 정설 → 유아 라인은 **1·4 → 2·3 순서**가 합리적.

## 3. 음원 경로 — 결론: 이미 검증된 Google Cloud TTS

한/영은 R2 라이브러리(`mod_korean`·`mod_english`·`mod_phonics`)에서 낱소리를 직행으로 뽑고 blend 만
서버 concat 한다. **병음은 각 음절(mā)이 이미 온전한 발화 단위**라, blend concat 은 성모+운모 시연용
(m→ā→mā)에만 쓰고 낱 음절은 직행이 정석.

- 🔴 **`cmn-CN-Chirp3-HD-Leda` 가 이미 있다** — `google-tts.provider.ts` `VOICE_BY_LANG.zh`,
  다국어 어휘 게임에서 **STT 되받아쓰기로 낱단어 인식 0.83~0.98 검증**(2026-07-12 주석). Gemini TTS 의
  짧은 CJK 무응답 이슈를 이 보이스가 이미 우회한다. **성조 정확도가 학습앱 수준**이라고 코드 주석이 명시.
  → 성조 음원 품질이라는 최대 리스크가 **이미 해소돼 있다**.
- **권장 경로**: 커리큘럼에 쓸 음절(초급 ~120개 × 성조)을 한 번 구워 R2 `mod_chinese`(신규 카테고리)에
  박고, 한글 `getKoreanSyllableUrl`·영어 `getEnglishPhonemeUrl` 과 대칭인 `getChineseSyllableUrl` 직행.
  실측된 "파닉스는 로딩 게이트 없음 → 워밍 빠뜨린 소리는 그대로 늦음"(memory `phonics-english-library-direct`)
  때문에 **직행이 반드시 필요**(런타임 concat/TTS 만 두면 첫 탭이 늦다).
- **zip 활용**: part-2(n~z) 202음절은 **파일럿 톤 비교·백업**으로. 성우 톤이 마음에 들면 a~m 절반만
  추가 소싱하면 되지만, TTS 가 이미 전 매트릭스를 균질하게 커버하므로 **굳이 섞을 이유는 약하다**
  (톤 불일치 위험 > 이득). 하나로 통일 권장.
- 손대는 서버 코드(전부 작은 diff): `PhonicsAudioCategory` 에 `mod_chinese` 추가 · 클라 `resolveTtsUrl`
  언어 유니온에 `'zh'` 직행 분기 · `google-tts` 는 zh 가 이미 있어 무변경.

## 4. 🔴 한자(汉字) — 노출 여부가 라인 성격을 가른다 (결정 항목)

병음 파닉스는 **한자 학습과 별개다.** 병음은 발음을 로마자로 적는 체계고, 한자는 표의문자다. 4~5세
병음 라인에서 한자를 어떻게 다루느냐로 세 갈래:

| 안 | 타겟 단어 표기 | 성격 | 비고 |
| --- | --- | --- | --- |
| **A. 병음 + 그림만** | `māma` + 엄마 그림 | 순수 발음 파닉스 | 한/영 라인과 완전 대칭. 가장 단순. 🔴 **권장 기본** |
| **B. 병음 + 한자 병기** | `妈妈 māma` + 그림 | 발음 + 글자 노출(읽기 X) | 한자를 "그림처럼" 곁들임. 표기 자산만 추가 |
| **C. 한자 중심** | 妈妈(병음은 보조) | 문해 라인 | 🔴 **병음 파닉스가 아님** — 범위 밖, 별도 프로젝트 |

중국 현지 1학년은 병음을 **한자 읽기의 도구**로 먼저 배우지만(部编版 순서), 앱의 4~5세 파닉스 라인은
**소리↔병음글자 연결**이 목표라 A 가 한/영 파이프라인(단어 카드 = 그림+병음, 게임 4종)에 1:1 맞물린다.
B 는 "한자 맛보기"로 마케팅 가치가 있으나 표기 자산(한자 폰트는 Noto SC 로 이미 됨)만 늘 뿐 활동은 A 와 동일.

## 5. 타당성 결론 — 재사용률

### 5.1 한/영 대비 재사용 (%)

| 축 | 재사용 | 비고 |
| --- | --- | --- |
| 언어 등록·폰트·TTS 보이스 | **~100%** | `zh` 등록됨 · Noto SC/ZCOOL 폰트 있음 · cmn-CN 보이스 검증됨 (한/일엔 없던 상태) |
| 데이터 스키마/타입 | ~90% | 한/영과 같은 `{level,name,units:[{id,title,phonemes,patterns,sampleWords,blending}]}` |
| blend/CVC 활동 | **~75%** | 성모+운모 블렌딩 = 영어 CVC·한글 합치기와 같은 구조. **가나처럼 뺄 게 아니라 그대로 씀** |
| listen/write/hunt/word-choose/게임4 | ~80% | 컴포넌트 재사용. splitUnits·블록·쓰기·그림짝 그대로 |
| 음원 인프라 | ~70% | 라이브러리 직행 경로 재사용 + `mod_chinese` 카테고리 1개 · TTS 는 이미 있음 |
| 단어 카드 → 게임 연동 | ~90% | rembg keypoints · link 스크립트 그대로(그림+병음 카드) |
| **성조 활동** | **~40% (일부 신규)** | 듣고 고르기 컴포넌트 재사용 가능하나 **성조 곡선 트레이스는 신규**. 병음만의 축 |
| **커리큘럼·단어 카드 콘텐츠** | **0% (신규 저작)** | 최대 비용 — 부편판 순서 유닛 + 유닛당 낱말 + 카드 이미지(사용자 GPT). 한글 나무 32유닛 급 저작 |

**총평**: **코드 난이도는 한/영과 비슷(성조 활동만 +α)하고, 인프라 재사용률은 신규 언어 중 최고**
(zh 가 이미 3종 다 깔려 있어서). 총 공수는 **콘텐츠 저작 + 성조 활동 설계**가 지배한다.

### 5.2 걸림돌 (우선순위)

1. **한자 노출(#4)·성조 범위(§2.3) 미결정** — 최우선. 커리큘럼·활동·카드 자산을 다 가른다.
2. **성조 학습 활동 설계** — 기존 활동으로 못 덮는 유일한 부분. 성조 곡선 트레이스 신규 + "듣고 성조
   고르기" 컴포넌트 개조. 유아 성조 변별(2성↔3성)이 원래 어렵다는 걸 UX 로 완화해야.
3. **커리큘럼·단어 카드 콘텐츠 저작** — 부편판 순서를 4~5세용으로 재편 + 유닛당 낱말·카드 이미지.
   한/영 파이프라인(`link-*-word-cards`·keypoints)은 그대로라 방식은 검증됨, 규모가 비용.
4. **병음을 별도 표시 축으로 둘지**(`splitUnits` 의 zh 는 한자 1자=1유닛) — 병음 라틴 문자열과 한자
   유닛이 다른 게임을 타므로, 병음 유닛을 zh 한자 처리와 섞지 말 것. 착수 시 작은 분기.
5. **plan 미등록 = 죽은 코드** — 한/영에서 반복된 함정(memory `phonics-english-write-screens`). 유닛·활동을
   만들면 **그 날 커리큘럼 generator + 호스트 분기 + 랜딩 카드**까지 도달 가능하게.
6. **zip 은 절반짜리** — part-1(a~m) 없음. 음원은 zip 이 아니라 TTS 로 통일(§3). zip 을 정답으로 착각 말 것.
